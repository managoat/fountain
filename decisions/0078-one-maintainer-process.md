# 0078 — A one-maintainer process

**Status:** Accepted, 2026-10-15. Supersedes [0050](0050-a-merge-queue-tests-what-it-merges.md).
Amends [0068](0068-relicense-the-server-under-apache.md): the DCO sign-off it
kept is dropped. Built. The repository settings that go with it (the
ruleset's merge queue and review rules, the DCO app, Review Loop's
variables) are external state the maintainer changes by hand.

## Context

Managoat is a self-hosted project with one maintainer. It stopped being sold
as a hosted service on 2026-10-12, its teams and billing are gone, and the
outside contributors and tenants it was preparing for are not coming. Most of
the repository's process was built for that other future, at a scale of
tens of merges a day from several people and many agents:

- **Review Loop** (`.github/workflows/review-loop.yml`, `.github/review/`)
  dispatched every PR to a hosted reviewer with five personas, its own
  sandbox setup and a repository skill for working with its bot commits.
  It needed a deployed service, a GitHub App and repository variables.
- **The DCO gate** (`scripts/ci/dco.py`) refused a PR with an unsigned
  commit. A DCO certifies where an outside contribution came from; with one
  maintainer there is no outside contribution to certify.
- **Changelog fragments** (`changelog.d/`, `scripts/changelog.py`) existed
  because the `[Unreleased]` section of `CHANGELOG.md` was the most common
  merge conflict on main. They brought a CI guard, a label to get past it, a
  roll step in the release and a required fragment on most PRs.
- **Label sync** (`.github/labels.json`, `scripts/sync-labels.py`) kept a
  taxonomy of labels the same across a team's issues.
- **The merge queue** ([0050](0050-a-merge-queue-tests-what-it-merges.md))
  tested each merge result because half of what landed on main had never
  been tested as a tree at 26 merges a day. It required an approving review
  before a PR could enter, which one person cannot give their own PR, so in
  practice every merge here was an admin merge that skipped the queue.

Each of these costs something on every change: a step to remember, a check to
satisfy, a setting to keep in step with a workflow.

## Decision

Remove the contributor-scale process and keep what protects the product:

1. **Review Loop is removed**: its workflow, configuration, reviewer
   personas, setup scripts, their tests and the repository skill.
2. **No DCO.** Commits need no `Signed-off-by:` trailer and CI does not
   check for one. Contributions are still under the Apache License, section 5
   of which covers them.
3. **No changelog fragments, and no `CHANGELOG.md`.** Each release's notes
   are generated by GitHub from the titles of its pull requests
   (`generate_release_notes` in `release.yml`). A release that needs upgrade
   steps gets an **Upgrade notes** section written at the top of its GitHub
   Release. The old file, with the upgrade notes for releases up to 0.23.0
   that only it carried, is at
   [v0.29.0](https://github.com/managoat/managoat/blob/v0.29.0/CHANGELOG.md),
   and the upgrade guide links there; `/docs/changelog` redirects to GitHub
   Releases. The TypeScript SDK keeps its own `sdk/typescript/CHANGELOG.md`.
4. **No label sync.** The labels on GitHub stay as they are and are managed
   there. The SDK release gate's `release:skip-sdk` and `sdk-no-release`
   labels, Dependabot's labels and the flake template's labels keep working
   because nothing deletes them.
5. **No merge queue.** A change lands through a pull request with green CI,
   and the maintainer merges it with an admin squash merge
   (`gh pr merge <N> --squash --admin`). No approving review is required.
   CI keeps its PR plan, docs-only classification and the `CI required`
   aggregate; it loses the `merge_group` event and the `already-tested`
   shortcut, so every push to main runs the full suite before an artifact is
   published for that sha. Only a release deploys
   ([0080](0080-prod-deploys-releases.md)).
6. **A release is one workflow run.** `release-bump.yml` checks that main's
   CI passed on the commit it releases, bumps the version and the image pins
   in one commit, and pushes that commit to main and its tag with the
   maintainer's token, which fires `release.yml`. There is no release pull
   request.

The rest of CI stays: test partitioning and the coverage gate, the SDK
contract layer, the SDK release gate, the secret scan, the Homebrew and
multi-arch release, and the ADR archive.

## Consequences

A change costs a PR, a green CI run and one merge command. Nothing waits on
an approval that cannot come.

Main again accepts trees no CI run tested as a tree: a PR that was green
against an older main can merge onto a newer one. With one maintainer and a
handful of merges a day the window is small, and main's own CI run, which now
always runs the full suite, catches what it lets through before anything is
released. A red main is fixed forward.

Every main push now pays for a full CI run, where the queue's tree proof let
most of them finish in seconds. That is one run per merge, the same count the
queue paid in its own `merge_group` build.

Release notes lose the hand-written prose of the changelog. A PR title has to
be readable as a release note, and upgrade notes depend on the maintainer
adding them to the release.

Pushing to main is a maintainer bypass, and so is the release workflow's
push: the ruleset has to let the maintainer and the release workflow's token
through. The repository rules stop being something CI checks for itself
(`scripts/ci/require-checks.py` goes with the queue) and are set by hand.

## Alternatives considered

- **Keep the merge queue and drop the review requirement to zero.** Every PR
  would reach the queue without an admin merge. 0050 rejected this to keep a
  human reading each change; with one maintainer that human is the author,
  and the queue's tree proof is not worth a second full CI run per merge and
  a merge that waits.
- **Keep `CHANGELOG.md` and edit `[Unreleased]` directly.** The conflict that
  motivated fragments is gone with one maintainer. It keeps a file to edit
  on every user-visible change and a roll step in the release; generated notes
  need neither.
- **Keep the DCO as a habit without the gate.** A trailer nobody checks
  certifies nothing.

## History

- 2026-10-15 — Decided and built in two pull requests: Review Loop, the DCO
  gate, changelog fragments and label sync removed (items 1 to 4); the merge

- 2026-10-15 — A push to main publishes an artifact and only a release

- 2026-10-15 — `CHANGELOG.md` and the manual's changelog page removed; the
