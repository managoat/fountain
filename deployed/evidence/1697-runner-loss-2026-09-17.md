## Surviving journal

itself. Its cleanup manifest survived. A fresh `deployed/cli.mjs cleanup`
process replayed that manifest and removed the environment. A second fresh
process replayed the updated manifest. Both returned `passed`,
`remaining: 0`, `failures: []`.

## No usable journal or uploaded artifact

Run B created an environment, an agent configured for
`claude` / `anthropic/claude-haiku-4-5` / `sprites` / `ephemeral`, and a
conversation with those exact parents. It submitted no prompts.

The fault wrapped `Client.request`: after the conversation POST returned
201, it sent itself `SIGKILL` **before returning the response to
`Fixtures.create`**, so the conversation's returned ID was never saved by
the fixture journal. This simulates a committed create whose response is
lost at the client/journal boundary; it is not a network partition test.
The supervisor then removed that child's entire evidence directory without
reading or copying its contents. There was no uploaded artifact. Only the
operator's target/account/run UUID, exact three-call program and kill
checkpoint survived independently.

Fresh `recover-fixtures.mjs inventory` discovered the exact markers through
public list APIs. The operator corroborated the three expected intents with
the bounded launch program, filled the evidence notes, read the conversation
and sandbox identities, waited for the already-created sandbox to reach
`ready`, and verified the conversation had zero turns. Reconstruction
made only GET requests and produced a new cleanup journal.

## Evidence and limits

[The sanitized summary](1697-runner-loss-2026-09-17.json) records process
exits, fixture counts, cleanup verdicts and final sandbox status. The original
lost-run evidence directory is absent by design. Exact identities, credentials
and raw API responses are not included in this committed record.

This live exercise covers surviving evidence, an ordinary ephemeral
conversation's lost create response, complete journal/artifact loss, public
ownership reconstruction and repeat recovery. Persistent home reset,
foreign/ambiguous ownership refusal, delayed create visibility and changed
dependents are covered by the focused HTTP harness, not claimed as deployed
results here. Unsupported profiles and unknown request settlement remain
explicit operator escalations in the procedure.

The live exercise predates the review fixes for source allowlists, children,
late-visible agents, Buzz identities, queue dependencies (including hidden
source overrides and parent conversations), account-wide queue settlement,
partial cleanup with cleared parent references, and source retention while
agent creates or cleanup remain unresolved. Those repairs have focused HTTP
harness coverage; the live results above are not a deployed test of those cases.
