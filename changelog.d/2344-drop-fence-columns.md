### Upgrade notes

- **This release drops two columns from `sandboxes`: `reset_requested_at` and `teardown_requested_at`** (#2344). A replica on a release before v0.20.0 reads both columns and fails every sandbox query once they are gone. v0.20.0 stopped reading them (#2423). So for a rolling upgrade, every replica must already run **v0.20.0 or later** before this migration runs: upgrade to v0.20.1 first and let it finish rolling. An upgrade that stops every replica before it migrates can come straight from an earlier release.
- **The drop also needs v0.20.1 or later, because v0.20.1, already released, ships the backfill that must run first (#2427).** The backfill stamps a deletion or reset that a v0.19.0 instance recorded only in these columns, so the reaper finishes it. This release's migrations include it, and it always runs before the drop. An upgrade through v0.20.1 runs it there. An upgrade straight from v0.19.0 runs both migrations in order, and that is safe too. Neither path needs operator action. The one request the backfill leaves unstamped is a reset on a machine that has run a turn since the request, and the drop discards it. The v0.20.1 upgrade note says how its owner can reset such a machine. A rollback of the drop adds the columns back empty.
